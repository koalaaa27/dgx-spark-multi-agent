# 项目计划书

## 一、项目背景与痛点
在软件开发领域，代码审查（Code Review）极其耗时且极其依赖人工经验。现有云端大模型方案存在数据隐私泄露风险和调用成本高昂的问题。团队希望借助 NVIDIA DGX Spark 强大的本地算力，构建一套完全本地化运行的多智能体（Multi-Agent）协作系统，提供安全、高效、即时的智能研发辅助。

## 二、项目目标与愿景
本项目旨在利用本地大模型，构建一个能像“AI 研发团队”一样工作的多智能体系统：
- 实现核心能力：支持代码生成、语法纠错、风格审查和安全漏洞分析。
- 实现本地部署：所有模型推理均在 DGX Spark 节点上运行，断网状态下亦可正常工作，确保核心数据永不外泄。
- 实现低门槛交互：提供 Web 界面，无需复杂环境配置，开箱即用。

## 三、技术架构与选型
- 硬件平台：NVIDIA DGX Spark 云节点（超强 GPU 算力 + 915GB 超大内存）。
- 底层推理：llama-cpp-python（GPU加速版本）。
- 应用框架：Gradio 搭建前端交互界面，FastAPI 提供后端接口。
- 核心模型：Deepseek-Coder-6.7B-Instruct（专为代码生成设计的开源大模型）。
- 部署方式：基于 Linux + Tmux 后台托管 + 国内镜像加速策略。

## 四、多智能体协作机制（核心亮点）
系统内部采用“多智能体分工”架构：
- 主管 Agent（Supervisor）：接收用户指令，拆解任务，并将请求路由给对应的专家 Agent。
- 代码审查 Agent（Coder）：核心执行者，负责代码格式检查、逻辑漏洞分析、安全风险扫描以及代码优化建议。
- 文档检索 Agent（RAG）：负责检索项目文档，为回答提供事实依据，减少大模型的“幻觉”问题。

## 五、项目实施与当前进度
目前已完成系统的核心部署与验证：
1. 环境搭建：成功在云节点完成环境隔离，部署 llama-cpp-python 与 Gradio。
2. 网络优化：针对国内机房网络限制，巧妙利用 hf-mirror.com 替换 HuggingFace 源，利用清华镜像源替换 pip 源，成功下载 70GB 级大模型并进行断点续传。
3. 服务启动：通过 Tmux 后台托管跑通大模型，成功监听 0.0.0.0:8888 端口，并通过公网成功访问。
4. 场景验证：成功对“冒泡排序”、“字符串回文判断”等代码任务进行了完整的生成与审查交互。

## 六、项目创新点
1. 完全本地化：数据不出机房，满足企业级代码和数据的隐私安全要求。
2. 高可用抗风险：采用断点续传、镜像加速、Tmux 后台托管等技术，确保资源受限环境下的稳定运行。
3. 敏捷协作：多 Agent 架构避免了单模型上下文过载，提升了复杂代码审查任务的处理效率。
